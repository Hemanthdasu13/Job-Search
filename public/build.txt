Could you tell if it was wrong? — v0.3.0 — what is in this build

Beta. The page is set to noindex, and the failing screen shows a reason code
for diagnosis. Both come out before the link is public.

If you are reading this, the deployment is current. If this 404s, Vercel has
not picked up the latest push and nothing below is live yet.

Access
  Off unless ACCESS_PINS is set, so the tool is open by default.
  When on: the landing page and the worked example stay open to everyone,
  and a key is asked for once, before anyone types anything. Never after -
  asking someone to write out an account of their own work and then telling
  them they cannot continue would be a trick, on a site about not being
  fooled.
  The check is on the server. /api/ask and /api/close refuse without a
  signed token, and ?stub=1 does not get past it either, so the key cannot
  be skipped by reading the page source or posting straight at the endpoint.
  A key buys a token good for ACCESS_HOURS (default 12), held for the tab
  only. Changing the key list invalidates every token already issued.
  Ten guesses an hour per address, shared across instances. A key is not
  protected by being short and secret; it is protected by that limit.
  A key is never tied to anything anyone types. What the owner learns is
  who asked them for one.

Contact
  The WhatsApp link points at /api/whatsapp on this domain, which redirects.
  A wa.me link carries the number in the URL itself, so putting one in the
  page would publish it to every crawler that harvests public pages. Set
  WHATSAPP_NUMBER in Vercel and it never appears in what a browser
  downloads; unset, the link is removed rather than left dead.
  This is not secrecy: anyone who clicks sees the number, because WhatsApp
  needs it. What it removes is the case where nobody clicked and it was
  collected anyway.

Bots
  The two endpoints that spend money, /api/ask and /api/close, refuse
  without a key once ACCESS_PINS is set, so traffic that does not have one
  costs nothing but a static file.
  /api/unlock allows ten attempts an hour per address.
  /api/diag?probe=1 and ?models=1 each spend a real model call, so they
  require ADMIN_TOKEN once one is set, and say so loudly while it is not.

Conversation
  Five statuses: probing, reached, verified, unclear, off_topic.
  Six probing turns maximum, then the gap-surfaced closing.
  The questions are steered across six dimensions: what the output was used
  for, what it was checked against, what it was told not to do, where it sat
  relative to what the person knows, what would have happened if it was
  wrong, and what using it actually bought them. Directions to ask in, never
  claims, never read out.
  reached closes on the turn it happens, even the first.
  verified closes to the independent-check screen.
  One vague answer buys a narrower question; a second in a row spends a turn,
  so non-answers cannot loop.
  Two off-topic replies end on the neutral screen, which offers a way back in.
  Three replies with nothing in them, in any mix, do the same: a conversation
  of non-answers must not arrive at a screen that names what did not come up.

Closing screens
  Fixed text, never generated.
  Your own words are quoted back on the two screens that close on them.
  A real outcome that already happened adds one short line above everything.

  The gap-surfaced screen can also name up to three practices from a library
  of seventeen. How that works, and what it cannot do:
    The library lives in the page. Every word of research in it was written
    by the researcher. There are seventeen cards; a card is shown only once
    its research has been written, and until then the screen falls back to
    the general closing. Nothing is generated.
    A second model call, to a separate endpoint, returns only a list of card
    ids and a quote from what you typed. It has no field to put a sentence
    of its own in.
    The server rejects any id outside the library, anything past three, and
    any quote that is not a span of your own text, character for character.
    A paraphrase is thrown away. Whitespace damage is forgiven; nothing else.
    The questioner is never shown the library, so a question cannot start
    carrying the research. A test asserts this.
    The screen says these are things that did not come up in your answers.
    It does not say you did not do them, because six questions cannot
    establish that.
    No type, no category, no score. The cards describe what is absent from
    one account of one decision, never the person who gave it.

Guarantees, enforced in code rather than asked of the model
  The model returns a question and a status and nothing else.
  At the close it returns card ids and your own words and nothing else.
  Every research claim on the page is fixed HTML the model cannot touch.
  No confidential detail is echoed back, in the question or the quote.
  Nothing typed is stored or logged by this site.

Contributing
  A conversation is kept only if the person ticks the box before typing.
  The box appears only where there is somewhere to keep one.
  What is kept: their words, the questions, how it ended, this version.
  What is never kept: any identifier. No IP, no session, no cookie.
  Kept conversations expire, and are reviewed by a person, never fed back
  into the tool automatically.

Testing without spending provider calls
  /?stub=1               walks the whole conversation on canned questions.
                         No provider call, so a free daily allowance is not
                         touched. Put #reached, #verified, #unclear,
                         #off_topic or #note in an answer to force that
                         branch. Use this for the screens, the routing, the
                         consent box and the closing text; spend real calls
                         only on judging the questions themselves.

What the page promises about data
  The privacy line is not fixed text. /api/config reports whether the
  configured provider uses what people type to train on, and the page says so
  itself when it does. Set PROVIDER_TRAINS_ON_INPUT=1 for a provider or tier
  that does. Google's Gemini API terms say unpaid use is used to "provide,
  improve, and develop Google products and services" and may be read by human
  reviewers, while paid use is not; Anthropic's API does not train on API
  inputs. A promise about data written once into HTML goes out of date in
  silence, which is the worst way for this page in particular to be wrong.

Changing provider
  Four variables, no code change:
    MODEL_API_KEY         the key, whichever provider it belongs to
    MODEL_ID              a model that provider serves
    PROVIDER_ENDPOINT     chat, for an OpenAI-shaped endpoint
    CHAT_COMPLETIONS_URL  that provider's full completions URL
  For Google's Gemini API the last is
    https://generativelanguage.googleapis.com/v1beta/openai/chat/completions
  The older OPENROUTER_ prefixed names are still read, so an existing
  deployment does not break. Check what the provider does with what people
  type before moving: a tier that trains on inputs contradicts what this page
  promises unless PROVIDER_TRAINS_ON_INPUT=1 is set too.

What each call costs
  a conversation         one call per turn, so two to nine
  /api/diag              none
  /api/diag?probe=1      one
  /api/diag?probe=both   two
  /?stub=1               none

Checking it yourself
  /api/diag              configuration, the deployed commit, the provider
                         account's own tier and limits, and how much of the
                         day's budget is spent
  /api/diag?probe=1      one real call to the configured endpoint
  /?debug=1              every turn's status, timing, build and failure reason
